# 태그 기능 확정 정의서

원본 `spec-original.md`에 대한 질의응답 결과를 반영한 확정본이다. 사용자가 직접 답한 항목(★)과, 사용자의 위임("나머지는 임의로 결정")에 따라 추천안으로 정한 항목(☆)을 구분해 표기한다.

## 기능 개요

노트에 태그를 추가하고 삭제할 수 있다. 태그는 노트 편집기(`NoteEditor`)에서 관리하고, 편집기에서 목록을 확인한다.

## 확정 사항

### 데이터 구조

- ★ `Note`에 `tags: string[]` 필드를 추가한다. (`src/types/note.ts`)
- ☆ 새 노트는 `tags: []`로 생성한다. `createNote`가 기본값을 채우며 호출자는 태그를 따로 넘기지 않는다.
- ☆ 기존 `db.json`의 노트처럼 `tags`가 없는 데이터는 읽을 때 `[]`로 간주한다. `db.json`을 일괄 수정하지 않는다.
- ☆ 태그는 추가한 순서를 유지한다.
- ☆ 별도 `/tags` 리소스는 만들지 않는다. 노트 삭제 시 태그도 함께 사라진다.

### 중복 및 정규화

- ★ 앞뒤 공백을 제거(trim)하고, 대소문자를 구분하지 않고 중복을 판정한다. `React`, `react`, `react`는 같은 태그다.
- ★ 저장되는 값은 사용자가 처음 입력한 표기(공백만 제거)를 유지한다.
- ☆ 중복 태그를 입력하면 추가하지 않고 입력창만 비운다. 사용자 알림(`alert` 등)은 쓰지 않는다.
- ☆ trim 후 빈 문자열은 추가하지 않는다.
- ☆ 태그 하나는 최대 15자로 제한한다(입력창 `maxLength`). 노트당 태그 개수 상한은 두지 않는다.
- ☆ 태그 이름에 쉼표는 허용하되 특별한 구분자로 취급하지 않는다. Enter만 추가 동작이다.

### UI

- ★ 태그 추가/삭제 UI는 `NoteEditor` 안에 둔다. 별도의 읽기 전용 상세 화면은 만들지 않는다.
- ★ 태그는 칩(chip) 형태로 보여주고, 삭제 `X` 버튼은 칩에 hover 했을 때만 나타난다.
- ☆ 칩 목록 아래(또는 옆)에 태그 입력창을 둔다. Enter로 추가한다.
- ☆ 키보드 접근성을 위해 `X` 버튼은 `focus-visible`일 때도 보이게 하고 `aria-label`을 단다(`"{태그} 태그 삭제"`).
- ☆ 한글 IME 조합 중 Enter는 무시한다(`e.nativeEvent.isComposing` 확인). 조합 확정 전에 태그가 중복 추가되는 것을 막기 위함이다.
- ☆ 입력창 `onKeyDown`에서 Enter의 폼 submit 기본 동작을 막는다(`preventDefault`).
- ☆ 목록(`NoteItem`)에는 태그를 표시하지 않는다. (원본 스펙에 없으므로 범위 밖)
- ☆ 스타일은 `src/index.css`의 `@theme` 시맨틱 토큰(`bg-card`, `border-border`, `text-muted-foreground`, `text-destructive` 등)을 사용한다. UI 텍스트는 한국어.

### 저장 시점

- ★ 태그는 `title`/`content`처럼 `NoteEditor`의 로컬 폼 상태(`tags`)로 들고 있다가, 저장 버튼에서 함께 저장한다. 추가/삭제 즉시 서버에 요청하지 않는다.
- ☆ 취소 시 태그 변경도 함께 버려진다.
- ☆ 수정은 기존 `updateNote(id, { title, content, tags })`(PATCH), 생성은 `createNote`를 확장해 태그를 함께 받는다. 시그니처는 신규 생성 쪽에서 `createNote(title, content, tags)`처럼 위치 인자를 이어 붙여 기존 방식과 맞춘다.
- ☆ 노트 선택이 바뀌거나 새 노트 모드로 전환되면 폼의 `tags`도 해당 노트 값으로 다시 초기화한다(기존 `useEffect`에 포함).
- ☆ 저장 시점에 입력창에 남아 있는(아직 Enter 치지 않은) 텍스트는 태그로 저장하지 않는다.
- ☆ 저장 실패 시 기존과 동일하게 `console.error`만 남기고, 폼 상태는 유지한다.

## 변경 대상 파일(구현 순서)

1. `src/types/note.ts` — `tags: string[]` 추가(주석 "강의에서 추가할 것" 제거)
2. `src/api/notes.ts` — `createNote` 기본 `tags: []`, 시그니처 `Omit`/`Partial` 반영
3. `src/context/NotesContext.tsx` — `createNote(title, content, tags)` 반영
4. `src/components/NoteEditor.tsx` — `tags` 로컬 상태, 칩/입력 UI, 저장 시 전달

## 범위 밖(이번에 만들지 않음)

- 태그로 노트 검색/필터링
- 태그 자동완성, 태그 이름 일괄 변경, 태그별 개수 집계
- 목록 카드의 태그 배지 표시
- 태그 개수 상한, 태그 색상

## 테스트 관점(구현 시 확인할 것)

- 태그 추가: Enter로 칩이 생기고 입력창이 비워진다
- 중복 방지: `React` 추가 후 `react`, `React`는 추가되지 않는다
- 빈 값/공백만 입력 시 추가되지 않는다
- 삭제: 칩의 `X`로 해당 태그만 제거된다
- 저장: 저장 시 PATCH 본문에 `tags`가 포함되고, 취소 시 변경이 버려진다
- 기존 노트(`tags` 없음)를 열어도 에러 없이 빈 태그로 표시된다
- 한글 입력 후 Enter 시 한 번만 추가된다
