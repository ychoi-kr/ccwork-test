# 태그 필터링 PRD

> 근거 문서: [`spec-fixed.md`](./spec-fixed.md) (확정 정의서). 선행 기능: [`../tag/prd.md`](../tag/prd.md). "기술 결정"은 ADR-001 하나를 채웠고(안 B 선택), "Out of Scope"는 사용자가 확정했다(노트 카드 태그 배지·하이라이트는 범위에 추가).

## 1. 개요

### 배경

`tag` 기능으로 노트에 태그를 붙일 수 있게 되었지만, 태그는 편집기 안에서만 보이고 쓸모가 없다. 노트가 늘어나면 특정 주제의 노트만 모아 보기 어렵다.

### 목표

- 모든 노트의 태그를 사이드바 상단에 칩으로 모아 보여 준다.
- 칩을 누르면 노트 리스트에 그 태그가 달린 노트만 표시한다.
- 노트 카드(`NoteItem`)에 그 노트의 태그를 배지로 보여 주고, 필터로 선택된 태그는 하이라이트한다.

### 성공 기준

- 여러 노트의 태그가 대소문자 무시로 합쳐져 가나다순 칩으로 보인다.
- 칩을 누르면 해당 태그가 달린 노트만 리스트에 남고, 다시 누르면 전체 목록으로 돌아간다.
- 선택된 태그가 어떤 노트에도 남지 않으면 필터가 자동으로 해제된다.
- 필터 조건에 맞지 않는 노트를 편집 중이어도 편집기는 유지된다.
- 태그가 하나도 없으면 태그 모음 영역이 보이지 않는다.
- 노트 카드에 그 노트의 태그가 배지로 보이고, 필터가 켜져 있으면 선택된 태그와 같은 배지만 하이라이트된다.

## 2. 사용자 스토리

| ID   | 스토리                                                                                                | 인수 조건                                                                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-1 | 노트 사용자로서, 내 노트에 쓰인 태그를 한눈에 보고 싶다. 어떤 주제가 있는지 파악하기 위해서다.        | 사이드바 상단에 모든 태그가 중복 없이(`React`=`react`) 가나다순 칩으로 보인다. 개수는 표시하지 않는다.                                                                                         |
| US-2 | 노트 사용자로서, 태그를 눌러 그 태그의 노트만 보고 싶다. 관련 노트를 빠르게 찾기 위해서다.            | 칩을 누르면 리스트에 해당 태그가 달린 노트만 남고 "노트 N개"가 줄어든다. 선택된 칩은 `aria-pressed="true"`로 구분된다.                                                                         |
| US-3 | 노트 사용자로서, 필터를 쉽게 풀고 싶다. 다시 전체 노트를 보기 위해서다.                               | 선택된 칩을 다시 누르면 전체 목록으로 돌아간다. 다른 칩을 누르면 필터가 교체된다.                                                                                                              |
| US-4 | 노트 사용자로서, 필터 중에도 편집하던 노트를 잃지 않고 싶다.                                          | 필터에 맞지 않는 노트를 편집 중이어도 편집기가 유지된다. 필터 변경은 `selectedNoteId`, `isCreating`을 바꾸지 않는다.                                                                           |
| US-5 | 노트 사용자로서, 태그를 고치거나 노트를 지운 뒤 막다른 화면을 보고 싶지 않다.                         | 선택된 태그가 더 이상 어떤 노트에도 없으면 필터가 자동 해제된다. 저장·삭제 직후 태그 모음과 리스트가 즉시 다시 계산된다.                                                                       |
| US-6 | 태그를 쓰지 않는 사용자로서, 빈 태그 영역을 보고 싶지 않다.                                           | 태그가 하나도 없거나 `tags` 필드가 없는 노트뿐이면 태그 모음 영역이 렌더되지 않는다. 로딩·에러 중에도 렌더되지 않는다.                                                                         |
| US-7 | 노트 사용자로서, 리스트에서 각 노트의 태그를 바로 보고 싶다. 노트를 열지 않고도 분류를 알기 위해서다. | 카드에 그 노트의 태그가 저장 순서대로 배지로 보인다. 태그가 없으면 배지 영역이 없다. 필터가 켜져 있으면 같은 태그(대소문자 무시) 배지가 하이라이트되고, 꺼지면 사라진다. 배지는 표시 전용이다. |

## 3. 기술 결정

### ADR-001: `useTagFilter` 훅 + `Sidebar` 컨테이너 기반 태그 필터

- **상태**: 제안됨 (아키텍처 3안 비교 후 사용자가 "안 B"를 선택)

#### Context

- 확정 정의서는 태그 모음(칩)과 노트 리스트가 같은 필터 상태를 공유하도록 정했다. 칩을 누르면 리스트가 바뀌고, 선택된 태그가 어떤 노트에도 없으면 필터가 자동 해제되어야 한다.
- 이 상태는 `selectedNoteId`, `isCreating`과 무관하다(필터 변경은 편집기에 영향을 주지 않는다). 즉 `App`이나 편집기가 알 필요가 없고, 사이드바 안에서만 쓰인다.
- 정의서는 자동 해제를 `useEffect`로 상태를 지우는 방식이 아니라 "선택된 태그가 유효할 때만 적용"하는 파생 계산으로 구현하라고 정했다. 칩 목록과 리스트가 서로 다른 시점의 결과를 보면 안 되므로 계산이 한곳에 있어야 한다.
- 노트 카드(`NoteItem`)도 선택된 태그를 알아야 배지를 하이라이트할 수 있다. 이는 선행 `tag` 기능의 "목록에는 태그를 표시하지 않는다" 결정을 이 feature에서 뒤집는 것이며, `NoteItem`은 상태 없는 표현 컴포넌트로 유지한다.
- 선행 기능(`tag` ADR-001)에서 팀이 React 내장 훅 기반 커스텀훅 합성을 선호하는 방향이 정해졌고 `src/hooks/`에 `useTags`, `useTagInput`이 이미 있다.
- 프로젝트 컨벤션: 컴포넌트는 UI 렌더링만 맡고 데이터 접근은 `useNotes()`로만 한다. 외부 상태 라이브러리, `useReducer`, 계산 메모이제이션(`useMemo`/`useCallback`)은 쓰지 않는다.

#### Decision

React 내장 훅만으로 커스텀훅을 만들고, 사이드바 컨테이너 컴포넌트에서 한 번 호출해 두 표현 컴포넌트에 props로 내려보낸다.

- **`useTagFilter(notes)`** (`src/hooks/useTagFilter.ts`)
  - 입력: `Note[]`. 반환: `{ tags, selectedTag, filteredNotes, toggleTag }`.
  - 내부 상태는 사용자가 마지막으로 누른 태그 문자열 하나(`useState`)뿐이다.
  - `tags`: 모든 노트의 태그를 대소문자 무시로 합쳐 중복 제거하고, 리스트 순서상 처음 나온 표기를 유지해 `localeCompare('ko')`로 정렬한 배열. `tags`가 없는 노트는 `[]`로 간주한다.
  - `selectedTag`: 저장된 문자열이 `tags` 중 하나와 대소문자 무시로 같으면 그 칩의 표기, 아니면 `null`(파생값). 자동 해제는 이 계산이 담당하며 `useEffect`로 상태를 지우지 않는다.
  - `filteredNotes`: `selectedTag`가 `null`이면 `notes` 그대로, 아니면 해당 태그를 가진 노트만.
  - `toggleTag(tag)`: 현재 `selectedTag`와 같으면 해제, 다르면 교체한다.
  - 서버, Context, 컴포넌트를 모르는 순수 상태 훅이다.
  - 대소문자 무시 태그 비교 함수 `isSameTag(a, b)`를 같은 파일에서 export하고, 훅 내부 계산과 `NoteItem`의 하이라이트 판정이 이 함수를 함께 쓴다(비교 규칙이 두 곳에서 갈라지지 않게 한다).
- **`TagFilter` 컴포넌트** (`src/components/TagFilter.tsx`)
  - `tags`, `selectedTag`, `onToggle`을 props로 받는 표현 컴포넌트. `tags`가 비면 `null`을 반환(early return)한다.
  - 칩은 `<button>`이고 `aria-pressed`로 선택 상태를 노출한다. 선택됨은 `surface_container_highest` 배경, 스타일은 디자인 시스템 토큰만 쓴다(`design-system` 스킬로 진행).
- **`Sidebar` 컴포넌트** (`src/components/Sidebar.tsx`)
  - `useNotes()`에서 `notes`, `loading`, `error`를 읽고 `useTagFilter(notes)`를 호출한다.
  - 로딩·에러가 아닐 때만 `TagFilter`를 렌더하고, `NoteList`에는 `filteredNotes`를 `notes` props로, `selectedTag`를 `selectedTag` props로 내려보낸다.
  - `selectedNoteId`, `onSelect`는 `App`에서 받아 `NoteList`에 그대로 전달한다(통과만 한다).
- **`NoteList`** 수정
  - 표시할 목록은 `notes` props로, 하이라이트 대상은 `selectedTag: string | null` props로 받는다. 로딩·에러·삭제는 기존처럼 `useNotes()`로 처리한다.
  - "노트 N개"는 받은 목록의 길이를 쓰므로 필터된 개수가 된다.
  - 각 `NoteItem`에 `selectedTag`를 그대로 전달한다.
- **`NoteItem`** 수정
  - `selectedTag: string | null` props를 추가로 받는다. 상태 없는 표현 컴포넌트로 유지한다.
  - 제목·내용 아래에 `note.tags ?? []`를 저장 순서대로 읽기 전용 배지로 렌더한다. 태그가 없으면 배지 영역을 렌더하지 않는다.
  - `selectedTag`가 있고 `isSameTag(tag, selectedTag)`이면 해당 배지를 하이라이트한다(디자인 시스템 토큰만 사용, 액센트 색 금지). 배지는 `<button>`이 아니며 클릭 동작이 없다.
- **`App`** 수정
  - `Layout`의 `sidebar` 슬롯에 `NoteList` 대신 `Sidebar`를 넣는다. `selectedNoteId`, `isCreating` 상태와 `NoteEditor` 연결은 그대로 둔다.
- **데이터/API/Context**: 변경 없음. `Note` 타입, `api/notes.ts`, `NotesContext`는 건드리지 않는다.

#### Alternatives

- **안 A. `App` 상태 + 순수 함수(`src/utils`)**: 거부. `selectedTag`가 `App`에 올라가면 `App`이 편집기와 무관한 상태를 갖게 되고, 유효성 검사를 `TagFilter`와 `NoteList`가 각자 호출해야 한다. 한쪽만 검증을 빠뜨리면 칩은 해제됐는데 리스트는 비는 식의 불일치가 생길 수 있다. 훅 합성을 선호하는 팀 방향과도 거리가 있다.
- **안 C. `NotesContext` 확장**: 거부. Context는 서버 데이터(`notes`, `loading`, `error`)만 담는다는 규칙에 UI 필터 상태를 섞게 된다. Context 값이 메모이제이션되지 않는 구조라 칩을 누를 때마다 모든 Context 소비자가 다시 렌더되고, 테스트도 Provider와 `fetch` mock이 필요해 무겁다.

#### Consequences

- **장점**
  - 칩 목록, 선택 상태, 필터 결과가 훅 한 번의 호출에서 같이 계산되어 어긋나지 않는다.
  - 훅을 `renderHook`으로 컴포넌트 없이 테스트할 수 있다(`useTags`와 같은 방식). `TagFilter`는 props만 받는 표현 컴포넌트라 테스트가 쉽다.
  - `App`, Context, API, `NoteEditor`를 건드리지 않아 변경 범위가 사이드바 안(`NoteList`, `NoteItem` 포함)에 갇힌다.
  - 칩 선택과 카드 하이라이트가 같은 `selectedTag` 파생값을 쓰므로 자동 해제 시 칩과 하이라이트가 함께 사라진다.
- **단점**
  - 파일이 늘어난다(훅, `TagFilter`, `Sidebar`). 이 규모에는 다소 무겁다.
  - `selectedTag`가 `Sidebar` → `NoteList` → `NoteItem`으로 두 단계 props로 내려간다(prop drilling). 소규모 앱이라 감수한다.
  - `NoteItem`의 props가 바뀌어 기존 호출부와 테스트(있다면)를 함께 고쳐야 한다. 카드 높이가 배지만큼 늘어난다.
  - `NoteList`가 목록을 `useNotes()`가 아니라 props로 받게 되어, 같은 컴포넌트 안에서 데이터 출처가 둘(`notes`는 props, `loading`/`error`/`deleteNote`는 Context)로 갈린다.
  - UI 상태 위치가 "UI 선택 상태는 `App`에 둔다"는 CLAUDE.md 서술과 다르다(`Sidebar` 내부). 필터는 사이드바 밖에서 쓰이지 않는다는 이유로 허용하며, 이 결정을 CLAUDE.md에 반영할지는 별도로 정한다.
  - 자동 해제가 파생 계산이라 저장된 문자열은 지워지지 않는다. 선택된 태그가 사라졌다가 같은 태그가 다시 생기면(예: 마지막 노트를 삭제한 뒤 새 노트에 같은 태그를 추가) 필터가 예고 없이 다시 켜질 수 있다. `Sidebar`가 마운트된 동안 유지되는 동작이라 새로고침 시에는 초기화된다.
  - `useMemo` 없이 렌더마다 집계·필터를 계산한다. 노트 수가 수백 개 이하라는 전제에서만 성립한다.

## 4. 용어 정의

[`spec-fixed.md`](./spec-fixed.md#용어-정의-ubiquitous-language)와 동기화한다.

| 용어        | 의미                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| 태그        | 노트의 `tags` 배열에 든 문자열 하나. 기존 `tag` 기능이 정의한 것을 그대로 쓴다.         |
| 태그 모음   | 모든 노트의 태그를 중복 없이 모아 칩으로 보여 주는 사이드바 상단 영역.                  |
| 태그 칩     | 태그 모음 안의 버튼 하나. 클릭 시 필터를 토글한다. (편집기의 태그 칩과는 다른 컴포넌트) |
| 필터        | 노트 리스트를 특정 태그가 달린 노트로 좁히는 상태.                                      |
| 선택된 태그 | 지금 필터로 켜져 있는 태그. 없으면 `null`(필터 꺼짐).                                   |
| 선택된 노트 | 기존 `selectedNoteId`가 가리키는 편집 중인 노트. 선택된 태그와 별개의 개념이다.         |

## 5. Out of Scope

이번에 만들지 않는 항목과 그 이유. 필요해지면 별도 기능으로 다룬다. 아래에 없는 항목도 요청 없이 미리 구현하지 않는다.

### 선택·필터 방식

- **다중 태그 선택(AND/OR)**: 단일 선택으로 확정했다. 규칙 결정과 UI·테스트 시나리오가 따로 필요하다.
- **"전체" 버튼 등 별도 필터 해제 컨트롤**: 선택된 칩을 다시 누르는 것이 유일한 해제 방법이다.
- **필터 상태 저장**: 새로고침 유지(`localStorage`), URL 쿼리 공유는 하지 않는다.
- **서버 쿼리 기반 필터링**: json-server `tags_like` 등 API 변경, `/tags` 리소스는 만들지 않는다. 필터는 클라이언트 계산이다.

### 태그 모음 표시

- **태그별 노트 개수 표시, 노트 많은 순 정렬**: 칩은 이름만 가나다순으로 보여 준다.
- **태그 색상, 아이콘, 칩 애니메이션** 등 장식 요소.
- **태그 검색·자동완성, 태그 이름 변경·삭제 등 관리 기능**.
- **칩 개수가 많을 때의 접기/펼치기, 스크롤 영역**: 사이드바 폭 안에서 줄바꿈만 한다.

### 다른 화면과의 연결

- **카드 안 태그(배지) 클릭으로 필터**: 카드 배지는 표시와 하이라이트 전용이며 클릭 동작이 없다.
- **카드 배지의 개수 상한, "+N" 접기, 배지 색상 커스터마이징**: 저장된 태그를 모두 보여 주고 줄바꿈만 한다.
- **편집기(`NoteEditor`, `TagInput`)의 태그 칩 클릭으로 필터**: 편집기 칩은 기존 `tag` 기능 그대로 둔다.
- **필터 변경 시 편집기 상태 조작**: 선택된 노트 해제, 편집기 초기화 등은 하지 않는다.

### 기존 코드 정리

- **기존 코드의 알려진 불일치 수정**: `Layout`의 인라인 스타일, 하드코딩 그림자, `NoteList`의 `console.error` 방식 등은 이 기능에서 고치지 않는다. 새로 만드는 파일에만 디자인 시스템을 적용한다.
- **CLAUDE.md 갱신**: UI 상태 위치 예외 등은 이 PRD 범위 밖이며 필요하면 별도 chore로 다룬다.
